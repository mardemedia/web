# I18n Architecture

This project keeps translation lookup at the route/page-data boundary and passes
ready-to-render copy into components as props.

The goal is to keep UI components decoupled from locale logic. Components should
not import translation helpers, inspect the active language, or build localized
URLs by themselves.

## Main Files

- `src/i18n/ui.ts`
  Stores translation labels for each supported language.

- `src/i18n/utils.ts`
  Defines supported languages and exposes `getTranslation(locale)`.

- `src/i18n/content.ts`
  Converts translation functions into typed copy objects such as `HomePageCopy`,
  `LayoutCopy`, `HeaderCopy`, and menu/navigation copy.

- `src/i18n/page-data.ts`
  Assembles complete page-level i18n data for routes. This is where translated
  copy, header/footer copy, brand assets, nav links, and language switcher data
  are composed. Smaller standalone pages, such as Coming Soon, also expose their
  copy from here.

- `src/pages/index.astro` and `src/pages/en/index.astro`
  Resolve the current locale, build localized URLs, fetch localized page data,
  and pass everything into `HomePage`.

## Data Flow

1. A route determines the current locale from `Astro.currentLocale`.
2. The route builds localized URLs, including the language switcher link.
3. The route calls `getHomePageI18n(locale, urls)`.
4. The route fetches locale-specific services and packages.
5. The route passes plain props to `HomePage`.
6. `HomePage` passes smaller copy objects down to layout and UI components.
7. Components render the provided copy without knowing where it came from.

## Component Rule

Presentational components should receive copy as props.

Good:

```astro
<Hero
  titleStart={copy.hero.titleStart}
  titleHighlight={copy.hero.titleHighlight}
  cta={copy.hero.cta}
/>
```

Avoid:

```astro
---
import { getTranslation } from "../i18n/utils";
const t = getTranslation(lang);
---

<h1>{t("hero.title.start")}</h1>
```

## Adding New Copy

1. Add the label in `src/i18n/ui.ts` for every supported language.
2. Add the field to the relevant copy interface in `src/i18n/content.ts`.
3. Map the label into that copy object in `src/i18n/content.ts`.
4. Pass the new prop from the page or parent component.
5. Render the prop in the child component.

## Adding New Pages

For a new localized page:

1. Create a copy interface in `src/i18n/content.ts`.
2. Add a function that maps labels into that interface.
3. Add a page-data helper in `src/i18n/page-data.ts`.
4. In the route file, resolve locale and localized URLs.
5. Pass assembled copy and data into the page component.

For standalone pages that do not use the main layout, still pass a copy object
into the component. `ComingSoon` follows this pattern with `ComingSoonCopy`.

## Navigation And Layout Copy

`Header`, `AsideMenu`, `Footer`, `LangButton`, and `IsotypeAnchor` are all
decoupled from locale-specific logic.

They receive:

- already translated labels
- already built URLs
- already selected brand assets
- already translated footer/menu text

This makes the layout reusable and keeps locale decisions in one place.

## Content Data

`src/data/services.json` and `src/data/packages.json` remain locale-keyed data
stores. Routes fetch the correct language data through:

```ts
await getAllServices(locale);
await getAllPackages(locale);
```

The resulting arrays are passed into page components as plain data.

## Notes

- Translation artifacts were cleaned from source content.
- Direct helpers like `getEnglishLabel` and `getSpanishLabel` were removed to
  discourage language-specific imports inside components.
- `routes.ts` now defines only the shape of a rendered route item. Translated
  route data is created in `content.ts`.
